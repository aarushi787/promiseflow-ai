# Demo walkthrough

1. Start the local demo and sign in as Production manager (`promise-demo`). Promise Checker is the default decision screen. Data is clearly synthetic.
2. Inspect Planning readiness. Unknown freshness and omitted models are disclosed. In Settings, a planner may record the source and actual confirmation time after reviewing inputs. Do not mark data confirmed merely to get a green result.
3. Review Production Plan and existing customer commitments. Enter a unique new order ID in Promise Checker, select gear shaft and a realistic quantity/date. Run the background check.
4. Read the result, best/proven delivery, readiness, causes and existing-customer impact. The active schedule is unchanged.
5. Run three separate recovery buttons: reoptimize approved alternatives, extend the bottleneck shift, and expedite incoming material. Compare delivery, configured cost change and worsened commitments. None is guaranteed to recover the date.
6. Review a proposal in Rescheduling. Export its decision evidence; enter a note to save or reject. Only manager/admin can approve and activate. The gate revalidates and rejects stale or incomplete work.
7. Simulate a resource breakdown in Disruptions. Review affected deliveries and operation moves before deciding. Do not approve merely for demonstration if using a real planning database.
8. Inspect Bottlenecks resource-by-day heatmap and expand a material's product/order/customer dependencies.
9. In Imports, download a template, change a sample value, preview, apply and undo before other edits. Export the approved delivery/operation reports.

Existing installed demo data is preserved. New solver results can differ from older saved plans after engine changes. Historical plans remain immutable; rebuild a proposal to evaluate the current engine. No customer notification or real commitment is made by a demo solve.
